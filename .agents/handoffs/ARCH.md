## ARCH-001-solid-rule-and-guard
SOLID rule and the arch guard · 2026-10-28 · c9c69ded2
- Changed: `.agents/specs/SOLID_GO.md` (S/O/L/I/D with repo examples, limits §8, mutable-state rule §9, god-type split recipe §10, don'ts §11; DIP stays owned by HEX §6). `internal/arch/solid_test.go` (`make arch`, part of `make all` and CI) parses `internal/` and `cmd/` and checks: methods ≤40 per type, fields ≤25 for a struct with ≥5 methods, interface ≤8 methods, package ≤12,000 lines / ≤60 files, no `init()`, no runtime-assigned package var, forbidden import edges (domain → adapters/application/platform/ports/ebiten/os; application and ports → adapters; outbound → inbound; ebiten sub-package → ebiten root).
- Decisions: `internal/arch/solid_budget.txt` records debt (60 lines at the start: 4 methods, 9 fields, 1 iface, 2 lines, 2 files, 16 init, 26 global). Ratchet (`judge`, `ratchet_test.go`): growth over a ceiling fails, a ceiling more than max(2, 5 %) above the measurement fails, a paid debt whose line remains fails, a new violation fails with the line to paste. Lines only shrink. A `var (...)` group holding a `sync`/`atomic` value, or an anonymous struct holding one, counts as guarded (mutex-guarded caches are legitimate, SOLID_GO §9).
- Why: the ebiten root was one 212-file / 64k-line package (`App` 111 fields / 950 methods, `Renderer` 74 / 398, 32-method sim port, 11 `init()`s); `game.Game` is worse (152 / 2105).
- Limits (blind spots, documented in the test): methods gained through an alias in another package are not counted; an embedded interface hides its methods; build-tagged files all count. `applyClick` has 23 prefix arms.
- Replaced the never-built `tools/archlint` (HEX §31).
