# MAPGEN-2: a field-based local map generator, debug views and fog of war

## Context
You pasted a full specification for natural-looking colony maps, built from the reference game's design principles. The goal is maps made of **large coherent shapes, medium patches and small irregular details**, generated by ordered passes that build on each other. Each pass gets its own random stream, and debug views show every intermediate field.

Your decisions:
- **The legacy generator stays frozen.** `Generate`/`GenerateBiome` keep serving tests, `-scenario` set pieces and old captures, with their hash pins intact. Every new-game (landing-site) map uses the new pipeline.
- **Debug views come in two forms:** an in-game developer overlay of each field over the live map, and a `cmd/mapgen` tool that writes PNG images (with seed grids and hilliness sweeps).
- **Scope:** the generation pipeline (§1–16), vegetation clusters and wildlife by habitat, natural mountain roofs (thin and thick), surface ruins, geothermal vents, stone-chunk debris, roads that follow world roads, start-spot scoring, validation and repair, and **fog of war**. **No** sealed "ancient danger" rooms this round.
- **Originality (AGENTS.md):** the spec quotes constants from decompiled reference code (frequencies, thresholds, rates). We use the *techniques*, which are generic procedural generation, with **our own numbers and names**, tuned by eye with the new debug views. No reference constant is copied.

### What exists today (verified)
**`internal/domain/world/generation`**
- `Generate` is the legacy temperate generator: 2-D value noise, a Chebyshev "edge" term, and fixed thresholds.
- `GenerateBiome` adds `rankGround` (ground mix by fertility rank).
- `GenerateSite` runs passes in this order: baseTerrain (hills table + one straight ridge band) → caves (3–6 constant-radius worms, no tapering, branching or size check) → coast (3 bands) → river (midpoint displacement, fords every 45 tiles, rock never cut) → lakes → wetGround → road (straight track to the centre) → safety (0-1 BFS carving to 70% reachability) → plants (one `IntN(1000)` roll per fertile tile against permille, no clustering).
- **One shared RNG stream:** base noise and plants both draw from it, so changing any pass moves every plant.

**Geology** (`internal/domain/world/geology`)
- Stones are already a per-stone value-noise argmax (cell 24).
- Ore veins grow as random 4-connected frontiers at rock depth ≥ 2.
- `roof.Natural` exists only for mined-out overhead rock; there is no thin/thick distinction.

**Noise and randomness**
- `pkg/noise` is 2-D value noise drawing its lattice from an RNG: map-size dependent, no octaves.
- `pkg/noise3` is hash-based 3-D value fBm, used by the planet.
- `pkg/randx` has no stream splitting.

**World tile**
- `site.Site` carries Biome, Climate, Hills (Default/Flat/Small/Large/Mountainous), River{Size, In, Out}, Coast, Lakes, Caves, Stones, Road, Latitude.
- The planet also knows each tile's elevation, rain and coast distance, but doesn't pass them to the site.

**Application** (`setup.go`)
- `ColonyBuilder` runs `GenerateSite` as one step, then `applySite` (terrain, geology, cave roofs), plants + grass + `spawnWildlife`, then finish.
- The start is the **map centre**.
- Grass is a per-tile hash (`plant/grass.go`).
- Wildlife uses `randomTileAway`, which ignores terrain.
- There is no fog, no power system (`domain/building/power` is an empty stub), and no map-image export tool.

**Tests**
- `site_test.go` covers behaviour (rivers edge to edge, no water at start, 70% reachable, caves only in rock, rock share rises with hills, coast bands, lake rings, fords, wet ground, road track). It also has the legacy equality tests `TestZeroSiteMatchesLegacy`, `goldenLegacy` and `TestFeaturelessSiteKeepsLegacyGround`.
- `BenchmarkGenerateSite500` has a budget of at most 2 s.
- `TestTemperateGenerationUnchanged` and the scale goldens use the legacy path and stay untouched.

## 1. Architecture: new package `internal/domain/world/mapgen` (pure, deterministic, headless)

```go
type Config struct {
    Seed          uint64      // setup seed (game.Setup.Seed) ^ generator version salt
    Width, Height int
    Site          site.Site   // world-tile input (biome, climate, hills, river, coast, lakes, caves, stones, roads, + new fields below)
    Version       uint16      // GenVersion = 2; stored in Setup so saved colonies never regenerate differently
}

type Fields struct {        // continuous model (float32 grids, row-major W×H)
    Elevation, MountainBias, Fertility, Wetness, VegDensity, ChunkDensity []float32
    RiverDist, CoastDist                                                  []float32 // tiles from centreline / shore (+Inf when none)
    RockDepth                                                            []uint8   // tiles to nearest open cell (0 = open)
    StartScore                                                           []float32 // start-spot suitability (debug)
    Stone      []geology.Stone   // material field argmax (every cell, used where rock exists)
    Cave, River, Coast, Lake []bool // masks
}

type Result struct {        // discrete outcome handed to the game
    Terrain   terrain.Map
    Roof      []roof.Cell       // Natural (thin) / NaturalThick on rock and on caves under rock
    Stones    []geology.Stone   // per rock cell
    Ores      []OreLump         // {Kind, Cells}
    Plants    []PlantSpawn      // existing type, now clustered (+Growth)
    Grass     []uint8           // initial grass mask (replaces the per-tile hash for setup games)
    Chunks    []ChunkSpawn      // {X,Y,Stone}
    Ruins     []Ruin            // {Walls []WallPiece{X,Y,Stuff,DamagePct}, Floors []FloorPiece, Loot []Stack}
    Vents     []Vent            // {X,Y} top-left of a 2×2 vent
    Roads     [][]Point         // smoothed centrelines (for the debug view); road cells are already Track terrain
    Start     Point             // chosen start spot
    Fields    *Fields           // kept when Config.Debug; nil otherwise
    Metrics   Metrics           // quality measurements (§9)
}

type Step interface { Name() string; Run(ctx *Ctx) error }
type Ctx struct {
    Cfg Config; F *Fields; R *Result
    Rand func(step string) *randx.Rand   // randx.New(fnv64a(seed, step)): one independent stream per step
    W, H int
}
func Generate(cfg Config) (Result, error)          // runs every step
func NewBuilder(cfg Config) *Builder               // Step(budget) per pass, for the loading screen
```

- **Independent streams:** every step draws only from `ctx.Rand("<its name>")`. Adding a boulder pass never changes the plants. No step iterates over a Go map, and slices are sorted before any random choice.
- **Version:** `Config.Version`, plus a per-version salt in the seed. `game.Setup` stores `GenVersion`, so debug-field regeneration for an older colony uses its own version or refuses.
- **New noise package `pkg/noise2`** (lead, Phase 0). It is hash-based 2-D **gradient** noise with no RNG draws, so it is order-independent and size-independent:
  - `Gradient(seed, x, y)`
  - `FBm(seed, x, y, octaves, baseCellSize, gain)` (octave 1 = largest scale)
  - `Ridged(...)`
  - `Warp(seed, x, y, amp, cell)`, which returns perturbed coordinates for domain warping
  - All output lands in [0, 1].
  - Tests cover determinism, range, smoothness (neighbouring-cell difference bounds) and spatial correlation; there is also a benchmark.

### 1.1 Pipeline order (`mapgen/pipeline.go`, lead-owned)
Each step lists what it consumes and produces:

| # | Step | Uses | Produces |
|---|---|---|---|
| 1 | `elevation` | site.Hills, site.MountainDir | Elevation, MountainBias |
| 2 | `fertility` | — | Fertility |
| 3 | `wetness` | site rain class, biome wetness | Wetness (base) |
| 4 | `material` | site.Stones | Stone |
| 5 | `rockmask` | Elevation (hilliness quantile) | provisional rock mask |
| 6 | `caves` | rock mask, site.Caves | Cave mask |
| 7 | `coast` | site.Coast | Coast mask, CoastDist |
| 8 | `river` | site.River, Elevation, rock mask | River mask, RiverDist, canyon carving of the rock mask |
| 9 | `lakes` | site.Lakes | Lake mask |
| 10 | `rocks` | rock mask − caves − water | final rock cells, cleanup, RockDepth, natural roofs |
| 11 | `terrain` | all fields and masks, by precedence | Terrain, then patch cleanup |
| 12 | `ores` | rock cells, RockDepth | Ores |
| 13 | `chunks` | ChunkDensity, rock proximity | Chunks |
| 14 | `roads` | site.Road, a cost grid | Track terrain, Roads |
| 15 | `start` | everything above | StartScore, Start (local repair if needed) |
| 16 | `ruins` | Start, roads, water, rock | Ruins |
| 17 | `vents` | Start, ruins, roads, water, rock | Vents |
| 18 | `vegetation` | Fertility, Wetness, VegDensity, terrain, Start | Plants, Grass |
| 19 | `validate` | everything | local repairs + Metrics |

- **Start before features:** the start is chosen after landforms and water exist, so features keep a distance from it and vegetation leaves its pad usable.
- **Wildlife** spawns in the game layer: it needs the animal roster and the game's RNG. The generator passes the start, reachability and habitat-friendly cells implicitly through the terrain.

### 1.2 World-tile inputs (additive `site.Site` fields)
- `MountainDir site.Dir8`, 0 = none: the bearing toward the highest-elevation neighbouring planet tile, set in `Planet.Site`. For Large/Mountainous tiles the mountain mass leans toward the actual uphill world direction; otherwise a seeded direction is used.
- `RainClass uint8` (0–4): from the planet rain, for the wetness base.
- `CoastWidth uint8`: from `CoastDist`, wider when the ocean is close.
- `Site.Zero()` semantics stay the same; the legacy path never sees these fields.

## 2. Landform passes (original numbers, tuned with the debug views)

### 2.1 Elevation and mountains (`elevation`, `rockmask`)
- **Base field:** `E0 = FBm(seed, warp(x, y))` with domain warping at amplitude 18 cells.
  - Three scales: macro (cell ~120 at 250² maps, scaled by `sqrt(W·H)/250` so a 500² map isn't simply zoomed), medium ~40, fine ~12.
  - Weights 0.55 / 0.30 / 0.15.
- **Mountain bias** `B` grows smoothly toward the `MountainDir` edge (a smoothstep over 45% of the map). It is noise-perturbed so the mountain face isn't a straight line, and for Mountainous maps a secondary lobe can wrap along an adjacent edge.
  - Weight by hilliness: Flat 0, Small 0.08, Large 0.18, Mountainous 0.38.
  - `E = normalise(0.85·E0 + w·B)`.
- **Rock share by quantile, not by a fixed threshold**, so every seed hits its profile:

  | Hilliness | Rock share of the map |
  |---|---|
  | Flat | ~4% (small outcrops) |
  | Small | ~10% |
  | Large | ~22% |
  | Mountainous | ~42% |

  Each share gets ±25% seeded variation. The threshold `τ_rock` is the elevation quantile giving that share. Two more bands sit just below it: `τ_rough` (rough stone ground, +6% share) and `τ_gravel` (gravel, +8%).
- **The start spot isn't known yet.** Rock may form anywhere, and the `start` step repairs locally if needed (§4).

### 2.2 Caves (`caves`), only when `site.Caves`
1. Flood-fill rock components on the provisional mask. Only components of **≥ 450 cells** qualify.
2. **Open tunnels** begin at a cliff cell facing open ground and head inward. **Closed tunnels** begin deep inside (RockDepth ≥ 6).
   - Per qualifying component: open tunnels = clamp(rock cells / 1800, 1, 3), closed = rock cells ≥ 3000 ? 1 : 0.
3. **Each tunnel:**
   - start width 3.5–5.5 cells, tapering by 0.045 per step to a minimum of 1.3;
   - heading turned by `Gradient` noise along its length (smooth bends, at most ±25° per 6 steps);
   - after ≥ 12 steps, a 7% chance per step to branch at ±(40–75)°, width ×0.7;
   - depth at most 3 branch levels;
   - it stops when width falls below 1.3, it would leave the component, it touches another tunnel (a small join), or it runs out of length budget.
4. Carving writes the **Cave mask** only; rock placement later skips those cells.
5. **Cave floors:** rough stone ground, with gravel patches (noise) and occasional shallow water where Wetness is high. Cave cells under rock keep a natural roof (§2.5).

### 2.3 Water (`coast`, `river`, `lakes`; wetness finishes after them)
**Coast** (per coast edge):
- Inland distance `d` is noise-perturbed by ±(6–10) cells along the edge at a large cell size.
- Bands: deep → shallow (4–7) → beach (sand; ice on cold biomes) whose width is noise-varied between 2 and 8. The base width comes from `CoastWidth`, 14–40 cells.
- A component check keeps the ocean connected to its edge.

**River:**
- The centreline runs from the In edge point to the Out edge point (U-shaped when In == Out). It is built in a rotated frame with lateral displacement `d(t) = A·(Gradient(t·f1) − 0.5) + A/3·(Gradient(t·f2) − 0.5)`, amplitude A = 0.10–0.16 × length, then sampled as a smooth polyline.
- **Width by size** (Creek / River / Large) with smooth variation ±20% along the length. Deep core 0 / 30% / 45% of the width.
- **Bank bands:** 1–3 cells of gravel/sand/mud by noise, plus a **fertile floodplain** of 2–6 cells of rich soil, wider on the inner side of bends (measured by local curvature).
- **Through rock:** the channel plus a walkable bank of ≥ 2 cells each side is cut out of the provisional rock mask. A large river in Large/Mountainous terrain becomes a **canyon**, with rock kept beyond the banks.
- **Crossing guarantee:** if a flood fill can't cross the river, convert the narrowest deep stretches to shallow (3–5 wide) until it can, at least every 60–90 cells.
- `RiverDist` is stored for the floodplain, wetness and the debug view.

**Lakes:**
- Keep today's behaviour (radius 6–14 noise blobs, deep/shallow, marsh or mud ring), now drawn from the step's own stream and placed away from rivers and coasts.

**Wetness:**
- `W = base(RainClass) × FBm + proximity(RiverDist, CoastDist, lake)`, which feeds marsh/mud patches and vegetation.

### 2.4 Material regions (`material`)
- One low-frequency `FBm` per permitted stone (cell ~180, scaled with map size). Each cell's stone is the **argmax**, and boundaries wander through domain warping.
- The result is 1–3 broad stone regions per map, never a cell-by-cell mix.
- It replaces geology's per-cell value noise for site maps. The legacy path keeps the old code.

### 2.5 Rock placement, cleanup and natural roofs (`rocks`)
- **Rock cells** = provisional rock mask − Cave − River/Coast/Lake water and banks.
- **Cleanup** (connected components):
  - Drop rock components of ≤ 5 cells, except on Flat maps, where 6–30-cell outcrops are kept as features.
  - Fill rock "holes" of ≤ 3 open cells inside rock.
  - Trim one-cell spikes: a rock cell with ≤ 1 rock neighbour among 4 is removed, iterated twice.
  - Edge irregularity is preserved: no smoothing beyond these rules.
- **RockDepth:** a Chebyshev BFS from open cells.
- **Natural roofs:**
  - **thin** (`roof.Natural`, existing) on rock cells and cave cells with RockDepth ≥ 2;
  - **thick** (new `roof.NaturalThick`, appended) where RockDepth ≥ 7.
- **Thick-roof gameplay:**
  - it can't be removed by the roof tools (`designateRoof` refuses with "Thick rock overhead");
  - drop pods and drop-in events never target it;
  - it never collapses;
  - it gives the "deep underground" look (no sky light).
- Mining a cell keeps whatever roof was there, as today.

### 2.6 Terrain classification (`terrain`, by precedence)
For each cell, the first match wins:
1. **Water:** coast (deep/shallow), river (deep/shallow), lake. Never overwritten.
2. **Rock wall:** rock cells; the stone comes from the field.
3. **Cave floor:** §2.2.
4. **Water edges:** beach sand/ice, river bank band, river floodplain rich soil, lake ring.
5. **Elevation bands:** `≥ τ_rough` gives rough stone ground (Stone); `≥ τ_gravel` gives Gravel.
6. **Biome patches (data-driven):** each biome lists patches `{Terrain, NoiseCell, Threshold, FertMin, FertMax, WetMin, MinSize}`. Examples:
   - swamp: marsh where Wetness ≥ 0.6;
   - wet low ground: mud;
   - arid: sand dunes where Fertility is low;
   - tundra: gravel scree.
   - Patch components smaller than `MinSize` are dropped.
7. **Fertility ground:** the biome's Ground mix applied by Fertility **quantiles**, as today's `rankGround`: rich soil on the most fertile share, then soil, then the poor-ground types.
8. **Fallback:** soil.

**Patch cleanup:** each terrain component smaller than its type's minimum (sand 6, marsh 8, rich soil 6, gravel 4, mud 5) merges into its surrounding majority type. The result has no one-cell checkerboard.

## 3. Resources and features

### 3.1 Ore lumps (`ores`)
- **Origins:** chosen inside rock at depth by ore kind:
  - steel: depth ≥ 2;
  - silver and machinery: depth ≥ 3;
  - gold: depth ≥ 5.
- **Spacing:** ≥ 6 cells between origins.
- **Budgets:** today's per-deep-cell counts are kept (they're our own balance).
- **Irregular lump:** grow a breadth-first frontier to `1.6 × size` cells, then repeatedly remove the cell with the fewest same-ore 4-neighbours (ties broken by the stream) until the size is reached. The lump is compact but not square. Every cell stays inside rock.

### 3.2 Stone chunks and debris (`chunks`)
- **`ChunkDensity`** = low-frequency FBm (cell ~60) × (1.6 near rock edges within 6 cells, falling to 0.6 in the open) × (1.3 on gravel or rough ground).
- Eligible cells are open, walkable, dry, not road, not within 12 of the start, and below `τ_rough`.
- **Rate:** per eligible cell, `p = 0.004 × ChunkDensity` (our number). On a hit, a short random walk places a small formation of 1–4 chunks (each on a new adjacent eligible cell).
- The chunk's stone is the material field at that cell.
- Chunks are ordinary items (`item.<Stone>Chunk`), each with its own sprite, never autotiled.

### 3.3 Roads (`roads`)
- **Endpoints:** for each road edge in `site.Road`, the edge point is the noise-shifted middle of that edge. Two or more roads meet at a junction near the start (within 20 tiles).
- **Route:** an A* over a cost grid:

  | Cell | Cost |
  |---|---|
  | open | 1 |
  | gravel / rough | 1.5 |
  | marsh / mud | 4 |
  | shallow water | 8 |
  | rock wall | impassable, or 25 to cut where no other way exists |
  | deep water | impassable (a river is crossed only at shallow cells; fords are made by the river step) |

- **Smoothing:** Chaikin corner cutting ×3 on the path, with a validity check (the smoothed path must stay off rock and deep water).
- **Rasterisation:** cells within 1.0 of the centreline become Track (2 wide). Edge cells within 1.6 become Track or Gravel by noise, so the edges are soft.
- The road must reach both its endpoint edge and the junction; this is validated.

### 3.4 Surface ruins (`ruins`) — small ruins only
- **Count:** 0–3 per map, weighted by biome (fewer on ice and extreme desert) and by planet population nearby (more near settlements).
- **Types, original designs:**
  - **Broken wall run:** 5–13 cells, straight or with one bend; 20–40% of its segments missing; damage 35–80%.
  - **Roofless shed:** rectangle 4×4 to 8×7; 30–55% of wall segments missing; at most one doorway gap; partial wood or stone floor inside (40–80% of interior cells), plus dirt, rubble chunks, and 1–3 loot stacks from a small table (steel 10–30, components 1–3, silver 20–60, cloth 5–15).
  - Wall stuff is wood or the local stone.
- **Placement:**
  - flat open ground (no rock, water or road within the footprint + 1);
  - ≥ 20 from the start;
  - ≥ 12 from other ruins and vents;
  - never across a river or blocking a road;
  - rejected if it would disconnect reachability (validated).
- **New `Building.Ruin bool`** (gob, additive). Ruined pieces:
  - are excluded from colony wealth, auto-Home and room ownership scores;
  - show "Ruined stone wall" in the inspector;
  - can be deconstructed (refund ×0.5 of normal).

### 3.5 Geothermal vents (`vents`)
- **Count:** 1–3 per map on Small, Large and Mountainous maps; 0–2 on Flat.
- **Placement:**
  - 2×2 on open, dry, non-road ground;
  - ≥ 18 from the start, ≥ 20 from each other, ≥ 12 from ruins;
  - not in rock or caves;
  - near rock edges preferred (a weight).
- **New construction kind `SteamVent`** (appended):
  - 2×2, `Natural` (not buildable by the player, not deconstructable, not movable);
  - walkable;
  - blocks building on its footprint.
- **In play:**
  - It vents steam in bursts: a sound and a particle effect, presentation only.
  - It warms the air: +1.5 °C per burst-average into its room, or +6 °C in the 5×5 outdoor cells around it, through the heat system's source list (`heat.go`).
- **Power:** none. The game has no power system yet, so the vent records `PowerReady` for a future geothermal generator. That gap is noted in the handoff and the checklist (`[-]`).

### 3.6 Vegetation (`vegetation`), hierarchical and clustered
**Biome data** (additive fields on `biome.Def`):
- `VegDensity` (0–1 overall target);
- group weights for trees, shrubs, ground plants and grass;
- per-species cluster radius and weight, minimum spacing and preferred terrain/wetness.
- Today's `Plants` permille list stays the species pool and commonality, and fills in defaults.

**Fields:**
- `VegDensity = biome.VegDensity × suitability(Fertility, Wetness, terrain) × C(x, y)`.
- `C` = smooth FBm (cell ~45) plus a warped "clearing" field, so clearings stay open.
- Trees use `C_forest` (cell ~35); shrubs use a tighter cluster field (cell ~10).

**Placement:**
1. Visit eligible cells in a shuffled order (the step's stream).
2. Reject cells that are:
   - occupied (rock, water, road, ruin, vent, chunk);
   - infertile for the species;
   - inside a cave (except species flagged as cave plants: none this round, moss allowed in damp caves);
   - within 6 of the start;
   - over **local saturation**: per 8×8 bucket, the plant count vs. the target from `VegDensity`.
3. Choose a species group by `P_group = groupWeight × groupField(x, y)`.
4. Choose a species by commonality × cluster boost: ×(1 + clusterWeight) if the same species is within clusterRadius, checked through bucket lookup.
5. Apply a **balance factor:** a species above its commonality share is down-weighted ×0.5; one below is up-weighted ×1.5.
6. Enforce **minimum spacing** per species: trees need no other tree in the 4-neighbourhood; large shrubs need Chebyshev 1; ground plants have no spacing rule.
7. Draw growth uniformly from 10–100% (trees 25–100%).

**Grass:** an initial grass mask from Fertility × Wetness × VegDensity with a biome base share. The game seeds its grass layer from the mask (Setup games only), replacing the per-tile hash there. Grass growth (PLAY-010) starts full.

**Targets** (by eye in the debug views):
- forests show groves and clearings;
- deserts are mostly bare with isolated hardy plants;
- swamps are concentrated on marsh and mud;
- ice sheets have almost nothing.

### 3.7 Wildlife (game layer, `wildlife.go`)
- For Setup games, herd spawn points are chosen by **habitat**:
  - walkable dry land reachable from the start (region labels);
  - not cave cells sealed under rock;
  - ≥ 25 from the start;
  - weighted toward grass and plant density for grazers;
  - predators spread across the map.
- Species come from the biome's wild pool. Domestic and pet species are excluded from natural spawning: check `pickSpecies` and add the filter if it is missing.
- The population cap (D15) is unchanged.
- The legacy path is unchanged.

## 4. Start spot, validation and repair (`start`, `validate`)
**Start score** on a coarse grid (every 4 cells; refined in the best 16×16):
- open buildable land within radius 12 ≥ 70%;
- reachability to a map edge;
- ≥ 25 cells from any edge;
- trees within 20;
- stone (rock or chunks) within 40;
- fertile soil within 20;
- no deep water, rock or vent within 4;
- a mild preference for the map centre.

The best score wins, with seeded tie-breaks. `StartScore` is kept for the debug view.

**If no cell passes,** a local repair runs:
- turn rock within radius 6 of the best candidate into rough stone ground;
- dry shallow water to mud;
- re-run reachability carving (today's `carve`, moved into `validate` and kept).

This makes the map playable, not safe: no protection beyond accessibility (spec §19.3).

**Structural validators** (each with a local repair):
- rivers are continuous edge to edge (gaps are reconnected along the centreline);
- the ocean is connected to its edge (stray water is dropped);
- no rock on water;
- ores only in rock;
- roofs only over rock or caves under rock;
- roads connect (re-routed if not);
- features don't overlap (a feature is moved or dropped);
- plants grow on valid terrain only (stragglers are removed);
- ≥ 70% of soft land is reachable from the start (carving as today).

**Metrics**, recorded in `Result.Metrics` and the debug tool (not hard failures):
- largest rock component share;
- count of tiny rock components;
- mean terrain patch size;
- open-space fraction;
- vegetation density per quadrant;
- tree cluster count;
- river curvature;
- stone material share;
- start accessibility.

**Profile tests** assert ranges over 30 seeds per profile, e.g.:
- Mountainous: largest rock component ≥ 55% of all rock;
- Flat: rock ≤ 8% and open space ≥ 70%;
- forest: tree clusters ≥ 4 on 250².

## 5. Fog of war (new, game layer + renderer)
- **State:** `fog []uint64` bitset (1 = hidden) on the Game, saved sparsely as hidden-run pairs.
  - Legacy colonies and old saves have no fog (all revealed). Only Setup games start fogged.
- **Initial reveal:** a flood from the start over walkable cells, with doors passing. It reveals every reached cell plus all 8-neighbours of reached cells (so cliff faces and walls are visible).
  - Open caves connected to the surface are revealed.
  - Sealed caves and rock interiors stay hidden.
- **Reveal on change:** when mining, deconstruction or a door opening makes a hidden walkable cell adjacent to a revealed one, flood-reveal that region (region-label based, bounded by the region).
  - A revealed sealed cave posts a message: "A cave opened up."
  - It is O(region size), triggered only by walkability changes (`structVer`/grid version).
- **Rules:**
  - Hidden cells hide their items, plants, animals and buildings in read models: `World()` and `Snapshot()` filter them, and AI still sees the truth.
  - Placement on hidden cells is refused with `ReasonFogged = "unexplored"`, except **mine designations on hidden rock**, which are allowed so the player can dig in.
  - Hover readouts show "Unexplored".
  - Colonists never path into hidden cells (they're unreachable by construction anyway).
- **Read model:** `WorldView.Fog []uint8` (copy-on-write via `shareLayer`) and `FogVer`.
- **Renderer:** hidden cells draw solid near-black (#0B0B0E) with a 1-tile soft edge, cached per chunk by `FogVer`. They are black on the minimap too. Selection, hover and the inspector ignore hidden things.
- **Tests:**
  - the start region is revealed and a sealed cave hidden;
  - mining into a cave reveals it (with the message);
  - hidden things are absent from the read models;
  - placement is refused except mining;
  - a save round trip;
  - old saves have no fog;
  - reveal cost is bounded;
  - the renderer draws hidden cells black and selection skips them.

## 6. Debug visualisations

### 6.1 `cmd/mapgen` (PNG tool; composition root, imports mapgen + biome + site + planet)
```
mapgen -seed 1001 -biome temperate_forest -hills large -size 250 [-river river:N>S] [-coast W] [-caves] [-stones granite,marble] [-road E,S] -out dir
mapgen -grid 12 -seed 1001 ...            # 4×3 contact sheet of consecutive seeds
mapgen -sweep hills -seed 1001 ...        # same seed: flat | small | large | mountainous
mapgen -tile <planetSeedText>:<tileID>    # generate exactly what a landing site would get
```
- **Field images, one PNG per field:**
  - elevation (grayscale);
  - mountain bias;
  - fertility (grayscale);
  - wetness (blue ramp);
  - rock-type regions (stone palette);
  - cave mask;
  - river and coast distance (ramp with the centreline drawn);
  - terrain classes (terrain palette = the minimap colours);
  - vegetation density;
  - plant placement (dots by group);
  - resources (ores, chunks, vents, ruins);
  - start suitability (heat map with the chosen spot);
  - region connectivity (a colour per reachable component);
  - natural roofs (thin/thick);
  - initial fog;
  - the final composite.
- **Report:** a `metrics.json` and a text summary.
- It is pure Go (`image/png`), with no Ebiten.

### 6.2 In-game developer overlay

- **Data:** the game regenerates the debug fields on demand from the saved Setup (`game.MapFields(name)`, run on a worker, then cached). The fields are never saved.
- **Rendering:** a world-space image over the map (alpha 0.7) with a small legend in the HUD.
- Read-only; dev mode only.
