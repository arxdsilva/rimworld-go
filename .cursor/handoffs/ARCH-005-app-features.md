# ARCH-005: the App's features leave the root

## Why
`App` had 950 methods over 126 files and 111 fields (ARCH-001): every HUD region, panel, screen and dialog was a method on it. Each feature becomes a package with one type behind a `Shell` composed of `ports` roles (`.cursor/SOLID_GO.md` §6–§7; ARCH-002 built the seam, ARCH-003 the leaves it draws with). The root keeps `App`, the loop, the navigator, the click routes and the screen table, and satisfies every role.

## Contract additions (lead)
`ports.Screen` with its names (the root's `screenID` aliases it), the navigation intents `Push/Back/StartGame/Quit/ReturnToMenu/Resume/Pause`, `ports.Widgets{Kit}`, `ports.Saves{Slots, RefreshSlots, LoadSlot, NewestSlot}` and `ports.SaveSlot`. A feature that needs something no role has declares ONE local interface (≤ 8 methods) in its `deps.go` that a small `<pkg>Host{a *App}` adapter in its root compat file satisfies.

## Wave 5.3 preparation (lead, before launch)
Seven feature packages and `render/world` moved at once (with ARCH-004 wave 4.4), so the lead laid every seam first and the tree stayed green throughout:
- A stub per package: `doc.go`, `deps.go` (`Shell` = the ports roles the plan names + `Host interface{}`; ≤ 8 members — the guard counts each embedded interface as one), the type and `New(sh Shell)`; a root `<pkg>_compat.go` with `<pkg>Host{a *App}`, `<pkg>Shell{shell; <pkg>Host}` and `new<Pkg>(a)`; `App` gained one pointer per feature (`opt`, `win`, `arch`, `ord`, `deal`, `lrn`, `tools`, `meter`) built in `NewApp`; `Renderer` gained `wp *world.Pipeline` built lazily by `r.pipeline()`.
- The App fields other root files read were moved by the lead into the stub types as exported fields and repointed root-wide with word-bounded perl (`a.workOpen` → `a.win.Open`, `a.panelMode` → `a.win.Mode`, `a.animalsWild` → `a.win.Wild`, `a.schedBrush` → `a.win.Brush`; the twelve `arch*` fields → `a.arch.Open/Cat/ToolID/Facing/Stuff/Crop/Drag/X0/Y0/X1/Y1/Ctrl`; `optionsTab`/`slots`/`slotsRead`/`saveSlot`/`autosaveDay` → `a.opt.Tab/Slots/SlotsRead/SaveSlot/AutosaveDay`): 21 fields, 758 sites, App 103 → 82 fields. Fields whose types live in the moving files (`float`, `search`, `form`, `rebind`, `dealings`, `dev`, `shot`, `archStyle`, `zone`, `bldgMove`, `hst.learn`) move with their agent, who writes the repoint lines for the lead (`scratchpad/w53/lead_edits_<pkg>.pl`) instead of editing files it does not own.
- Four root tests built `&App{}` literals and dereferenced the new pointers: they now construct through `testApp(nil)`.
- `needexport`/`usedin` per set (`scratchpad/w53/need_*.txt`, `used_*.txt`): run from the repo root with the RELATIVE package dir, and in zsh split a word list with `${=files}` — an unquoted `$files` is one word and both tools silently report nothing.

## Findings
- Waves 5.4 + 5.5 (two agents at once): App 67 → 57 fields and 732 → 607 methods, the root 107 → 70 files and 24.6k → 14.6k lines. Every planned feature package exists; what the root still holds is the composition (`app.go`, `shell.go`, `nav.go`, `hotkeys.go`, `colony_compose.go`, the boot/pause/loading screens, capture), the `<pkg>_compat.go` wrappers and converting shims, and `Renderer`'s orchestration — ARCH-006's sweep.
- Wave 5.3 (seven packages + `render/world`, eight agents at once): App 103 → 67 fields and 870 → 732 methods, the root 164 → 107 files and 36.7k → 24.6k lines; the whole tree green under `-race`, `DrawArt500/z1` 1.00 ms before and after with 418 draw calls and 3,826 allocs in both.
- An agent that exports the fields of a type the rest of the root still reads (`devState.menu` → `Menu`, `lodState.tier` → `Tier`) breaks every other agent's build until the lead repoints: in a shared checkout the lead applies such mechanical repoints the moment they are reported (word-bounded perl on the files that match, never `*.go`, so no concurrent edit is clobbered).
- Fields whose types move with the package cannot be pre-migrated; `orders` bridged the wave with copy-in/copy-out stand-ins around every wrapper and the lead deleted them after the root-wide repoint — it works, but a sole repoint agent (as `selection` had) is simpler when the field has many readers.
- The canvas guard's `hudFiles` globs now cover the feature packages (`windows/*.go`, `architect/*.go`, …) with the world-drawing files listed in `hudFilesNot`; the map-pixel guard accepts any pointer receiver except the converters themselves (`Renderer`, `globe/`, `render/`).
- Still root after this wave: `inspector` (hud_inspect, hud_commands, the six inspectors, the pawn tabs, `cmds_*`), `hud` (regions, alerts, letters, toast, colonist bar), `multiselect.go`'s group pane, the root wrappers in every `<pkg>_compat.go`, and the ebiten `AGENTS.md`, which still names the moved files (ARCH-006).
- A feature whose state other root files read (`selection`: 52 files) cannot be wired by a parallel agent: the field repoint is a serial, root-wide `perl -pi` per field — a sole agent's job after the package exists.
- The wizard and the Options story tab share the difficulty widgets (`diffSlider`, `diffCheck`, `diffStepper`, `textLines`, `declareOnScreenLayer`, the form context); they are pure kit composites over wizard-only button helpers, so the wizard move starts by lifting them into `uikit/form.go`.
